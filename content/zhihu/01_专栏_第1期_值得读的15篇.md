## 1. Muse Ember：小模型军备竞赛的本质是抢"Agent 日常动作"的单价

原文：[Introducing Our Smallest, Most Efficient Model: Muse Ember — Simon Willison](https://simonwillison.net/2026/Nov/10/muse-ember/)

Meta 发布了 Claude Haiku / GPT Luna 级别的 Muse Ember，官方定位原话是"为 agent 每天重复的工作设计"：tool calls、coding subtasks、routing、extraction、长文档解析。

真正值得抄下来的是 Simon 算的这笔账：

| 模型 | 短 prompt（$/M in / out） | 长上下文档（$/M in / out） |
|---|---|---|
| GPT-6 Luna（>272k） | 0.10 / 0.50 | 0.20 / 0.75 |
| Muse Ember（>200k） | 0.10 / 0.50 | **0.30 / 1.50** |
| Claude Haiku 5.5（>100k） | 0.10 / 0.50 | 0.50 / 2.50 |

短 prompt 下三家同价，一过阈值 Ember 跳到 $0.30/$1.50——比 Haiku 还是便宜，但已经不是"同一个价位带"了。**做长上下文 agent 选型时，这个跳价细节会直接改变成本结论**；而 token 单价之外，reasoning token 消耗量因模型而异，比单价更该看的是"每任务成本"。

## 2. 斯坦福 CS146S：当 Agent 能一键写完去年的作业，课程教什么？

原文：[How Stanford Teaches AI-Native Engineering — Latent Space 播客](https://latent.space/p/one_million_ai_engineer_special_how_stanford_teaches_ai-native_engineering_mihail_eric_monaco/)

本期最值得精读的一篇。开篇问题就很好：**"当 coding agent 一个 prompt 就能写完去年的作业，你给学生布置什么？"**

Mihail Eric（斯坦福 CS146S 讲师、Monaco AI 负责人）的答案：把真实开源协作变成课程本身——学生选一个陌生开源仓库，读懂它，提出一个变更，然后**向可能合并这个 patch 的 maintainer 解释它**。评分人就是开源 maintainer。

结合他在 Monaco 团队的实践，几个观点值得记下来：

- "买来学，留下来自建"（You buy to learn, and you build to keep）——工具选型的分界线；
- 给 on-call agent 直接接 Datadog 和 GitHub，前提是先把 repo 做成 agent-ready；
- 课程大纲里活下来的内容，是被自己工程团队的实战检验过的。

这是目前对"AI 时代工程师还该学什么"最认真的一份回答：**价值正在从"写代码"移向"理解、审查、解释代码"**。

## 3. BioBasicsBench：agent 评测的教科书示范

原文：[Measuring how AI agents handle everyday wet-lab science — OpenAI](https://openai.com/index/measuring-how-ai-agents-handle-wet-lab-science)

100 个来自真实实验室的任务：胶图、菌落照片、显微镜视频、仪器原始输出——刻意用论文里不会出现的**脏数据**。GPT-6 Astra 拿到 66.7% 平均分，看起来不错？看失败案例：

- 把培养皿边缘标签上的抗生素（kanamycin）认错了，基于错误的对照组下结论；
- 把显微镜的 z-stack 深度扫描当成"细胞消失了"去找生物学解释；
- 数菌落数错约 12%，因为分不开挨得近的菌落、漏掉可见菌落、还标记了空白琼脂。

这套基准在工程上至少有三点值得所有做 agent evals 的人抄作业：**rubric 逐项给分**（能区分"结论对了但过程错了"）、**raw data 而非精选数据**、**失败案例当一等公民发布**。比刷榜式 benchmark 诚实得多。

## 4. 浏览器四方联手：治一治 coding agent 的"2019 年代码病"

原文：[modern-web-guidance — GitHub（Chrome / Edge / Firefox / MDN 联合维护）](https://github.com/GoogleChrome/modern-web-guidance)

coding agent 生成过时代码的根因很清楚：训练数据里全是 legacy 模式。这个项目的做法值得抄——把现代 web 最佳实践做成 token 高效的 skill，按需注入 agent 上下文，再用 eval 闭环证明价值：各主流 agent 上 unguided → guided **提升 28~36 个百分点**。

这是"给 agent 注入专家知识"模式的官方样板：领域专家维护内容、有 eval 验证 uplift、不靠祈祷。

## 5. Resend 的 AEO 实践：机器可读性正在变成获客渠道

原文：[Designing for Agents — Latent Space 播客](https://latent.space/p/resend/)

一项研究里，Claude Code 的 102 次邮件方案推荐中 Resend 被选为第一顺位 64 次，老牌 SendGrid 只剩 7 次。Resend 靠的不是塞钱，是细节：**给定价页 URL 加个 `.md` 后缀**，让 agent 一次请求就能读懂数据。

"答案引擎优化"（AEO）对开发者产品已经不是营销玄学，是收入问题。做 API 产品的可以现在就自查：你的文档、定价页、报错信息，agent 读得懂吗？

## 6. AlphaProof Code：agent 可信度的一种数学解法

原文：[Introducing AlphaProof Code — Google DeepMind](https://deepmind.google/blog/introducing-alphaproof-code/)

多 agent 协作生成 600 万行 Lean 证明，第一次把广泛部署的密码协议（Signal）从"设计层验证"推进到"设备上运行的实际代码"级别，4 周完成过去专家团队数年的工作，人工复核只剩 1%。

对普遍的"agent 产出可信吗"焦虑，这个案例给的方向是：**不要人肉抽检 agent，让机器检查器（Lean 这类形式验证工具）来担保 agent 产出**。

## 7-15. 其余值得一看的

- **[llm-anthropic 0.31](https://simonwillison.net/2026/Nov/9/llm-anthropic/)**：Simon 的工作方式值得抄——新模型发布当天接入自己的工具链，用同一个任务把各推理档全跑一遍。一套人人可抄的"模型快速体检管线"。
- **[CodeRabbit 20x 吞吐案例](https://openai.com/index/coderabbit-codex-daybreak)**：营销浓度高，但隐含架构值得看——AI 生成代码后靠另一层 AI 治理，生成与验证分离。
- **[ChatGPT Desktop 转发 SSH 凭据事件](https://news.ycombinator.com/item?id=50422628)**（HN 216 赞）：便利与默认权限边界的经典冲突。给 agent 接工具前先想清楚哪些凭据永远不该进它的可达范围。
- **[6 小时 LLM 推理视频 + 85 页手打笔记](https://github.com/samir-sarwar/samir-vllm)**：想系统补推理侧底子（KV cache、调度、PagedAttention）的一站式材料。
- **[The Verge 主编的唱衰](https://simonwillison.net/2026/Nov/6/nilay-patel/)**：行业情绪温度计，刻薄但戳中要害——产品收益撑不起成本叙事。做 agent 的人不妨每月读一次唱衰，逼自己回答"用户为什么付费"。
- **[Cogent 自动修复漏洞案例](https://openai.com/index/cogent-security)**：一句话归档，与 AlphaProof 对照看——"自动修复"和"可验证正确性"是同一问题的两种解法。
- **[Yonkers Rises](https://simonwillison.net/2026/Nov/10/yonkers-rises/)**：玩具帖，但 Fable 5.2 把键盘手误 "átomos" 正确脑补成 "stomps"——这种鲁棒性比跑分更能说明代际进步。
- **[datasette-llm 0.1a10](https://simonwillison.net/2026/Nov/4/datasette-llm/)**：小版本新闻，背后是"agent 能用哪些模型"本身就是个权限治理问题。
- **[别让 agent 的 PR 描述淹没你](https://simonwillison.net/2026/Nov/9/details-summary/)**：agent 写的 PR 描述"好得过分"，Simon 用 `<details>` 折叠默认收起。指向大话题：生成速度超过 review 速度后，瓶颈正在移到 review 一侧。
