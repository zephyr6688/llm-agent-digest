先说一个真实发生的事。

斯坦福 CS146S 是一门给资深工程师开的课。去年，它的作业还是正常的编程作业。今年开课之前，授课的 Mihail Eric 面对一个问题：**coding agent 一个 prompt 就能把去年的作业全部写完，那这门课还布置什么？**

他的答案是把课程整个换掉：学生不再是"实现某个功能"，而是——

1. 选一个自己**不熟悉的开源仓库**；
2. 读懂它的代码和设计决策；
3. 提出一个真实的变更（不是玩具 PR）；
4. **向可能合并这个 patch 的开源 maintainer 解释你的改动**——评分人就是这些 maintainer。

注意第 4 条：这是很多在职工程师都没被真正考核过的能力。你在公司里写的 design doc、发的 CR，本质上就是这件事——把"我改了什么、为什么这么改、风险在哪"讲给一个有合并权的人听。

这不是孤例，同期斯坦福还有 CS329Z 这类 agent 工程课，讲的是任务分解、retrieval、tool use、agent loop、trace 收集和失败分析。两门课指向同一个趋势：**教学重心正在从"写代码"移向"理解、审查、解释代码"，以及"设计 agent 替你写代码时所处的系统"**。

再补一个在真实公司里的印证。这位讲师本人在 Monaco 带 engineering 团队，播客里他讲了一个选型原则："You buy to learn, and you build to keep"——工具买来是为了学习它背后的模式，真正核心的留给自建。他们给 on-call agent 直接接了 Datadog 和 GitHub，但前提是先把 repo 做成 agent-ready：文档结构、报错信息、运行环境都要让 agent 能读懂。

所以"AI 时代还学什么"，从这门课里能读出三层答案：

- **底子不变**：系统、网络、数据结构这些仍然是判断力的来源——你要能 review agent 的产出，前提是你比它更懂什么是错的；
- **新增的能力**：上下文工程（把什么样的信息、以什么形态喂给模型）、评测设计（怎么证明 agent 的产出可靠）、以及把真实系统改造为 agent 可操作的能力；
- **被放大的旧能力**：把复杂问题讲清楚。向 maintainer 解释 patch、向团队解释 design——这事 agent 暂时替你做不了，而且随着代码生成变便宜，它反而更值钱。

课程大纲和播客原文在这里（英文）：Latent Space 对 Mihail Eric 的访谈，[How Stanford Teaches AI-Native Engineering](https://latent.space/p/one_million_ai_engineer_special_how_stanford_teaches_ai-native_engineering_mihail_eric_monaco/)。斯坦福 CS146S 的课程大纲在其官网公开可查。

一句话总结：**代码生产正在变成按一下按钮的事，而"判断代码该不该长这样、向有权力的人解释清楚为什么"，正在变成这个职业的核心技能。**斯坦福这门课等于公开承认了这一点——这比任何预测报告都有说服力。
