分享一个我最近看到的、把 agent 评测做得非常认真的案例，从它身上可以反推出几条能直接用的工作原则。

OpenAI 和生物科技公司 Ligo 做了一个叫 [BioBasicsBench](https://openai.com/index/measuring-how-ai-agents-handle-wet-lab-science) 的基准：100 个来自**真实湿实验室**的日常任务——读凝胶电泳图的分子量、判断菌落照片、解读显微镜视频——测试 agent 能不能像实验员一样分析原始实验数据。

最有价值的是他们公开的失败案例。三个例子：

1. **模型把培养皿边缘标签上的抗生素认错了**（标签写的是 kanamycin，实验用的是 ampicillin），然后基于这个错误观察下了完整的一串结论；
2. 显微镜在做 **z-stack 深度扫描**（不同深度连续拍照），画面里的细胞因此忽隐忽现，模型把这当成"细胞消失"，煞有介事地去找生物学解释；
3. 数菌落时**数多了约 12%**：挨得近的菌落分不开、肉眼可见的菌落漏掉、还把空白琼脂标记成了菌落。

这些案例的珍贵之处在于：**它们在标准 benchmark 上根本测不出来**。读论文配好的干净图表，模型可以表现很好；但真实世界的数据是脏的、有歧义的、需要"先检查对照组是否成立"再下结论的。

从这个案例里，我总结出四条可以直接迁移到自己 agent 评测上的原则：

**1. 用 raw data，不要用精选数据。**评测集应该长得像你的真实输入，而不是像教程里的示例。精选数据高估 agent，脏数据低估你自己。

**2. Rubric 逐项给分，而不是整体判对错。**BioBasicsBench 的每个任务有专家写的评分细则，能区分"结论对了但过程完全错误"和"结论对且过程也对"。整体给分会把这两种情况混在一起，你就永远不知道该修模型还是修流程。

**3. 把"证据不足时不下结论"设为评分项。**这套基准里，识别"这个数据根本支撑不了任何结论"本身就是得分点。大多数 agent 评测漏了这一项，导致 agent 学会了强行下结论的坏习惯。

**4. 失败案例是一等公民，值得公开发布。**比起"我们的模型得了 66.7%"，那三个失败案例对做工程的人有用十倍。你自己的评测报告也应该有 failure case 分析章节。

顺带一提，做评测方向想系统学习的话，Hamel Husain 的博客（hamel.dev）是目前这个领域公认最好的免费材料，比任何大会 talk 都实在。
